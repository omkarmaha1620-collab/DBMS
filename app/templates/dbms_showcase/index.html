5. Relational Normalization & DBMS Concepts Demonstrated
A. Relational Normalization (3NF / BCNF)
  • 1NF: All attribute values are atomic (e.g. no arrays, multi-valued fields). Primary keys defined on all 10 tables.
  • 2NF: No partial dependencies. Composite relationships decomposed into junction table class_subject_teachers and fact table attendance.
  • 3NF: No transitive dependencies. Derived values (e.g. attendance percentage) are not stored redundantly in tables; computed dynamically via SQL Views and Stored Procedures.
  • Referential Integrity: ON DELETE CASCADE for 1:1 user-profile links and notifications; ON DELETE RESTRICT for classes to safeguard active enrollments.
B. ACID Transactions & SQL Operations
  • Transactions (Atomicity): Attendance marking commits all students in a classroom inside a single atomic unit. If any error occurs, connection.rollback() is triggered immediately.
  • Multi-Table Joins: Core queries employ 3 to 5-way INNER JOIN and LEFT JOIN linking students, classes, subjects, teachers, and users.
  • Aggregation & HAVING: Defaulter calculation utilizes SUM(CASE ...), COUNT(), GROUP BY, and HAVING attendance_percentage < threshold.
  • Subqueries: Scalar subqueries retrieve dynamic cutoff thresholds from system_settings.
